\CM{} runs on one Windows PC, for one user, without administrator rights
(figure~\ref{fig:deployment}). The NSIS installer puts the shell and the
bundled runtime files (in \texttt{bundle\textbackslash}) into
\texttt{\%LOCALAPPDATA\%\textbackslash Cover\_Maker}, the Tauri default for a
per-user install; the runtime and the user data that the app creates live in
sub-folders of the same directory.

The release workflow (\texttt{.github/workflows/release.yml}) runs on a
\texttt{v*} tag: it stages the bundled files with
\texttt{desktop/scripts/prepare-runtime.ps1}, builds and signs the installer
and the updater manifest, mirrors the ffmpeg archive and attaches the six PDF
documents to a draft release, which a maintainer publishes by hand. The
uninstaller removes the runtime folder and, only when \emph{Delete the
application data} is ticked, the user data too. ADR-006 explains the bootstrap.
