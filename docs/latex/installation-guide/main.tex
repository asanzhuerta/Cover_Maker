\CM{} needs the Microsoft Edge WebView2 runtime, which is part of Windows 10
(since 2021) and Windows 11; the installer downloads it when it is missing.
For the GPU path, install a current NVIDIA driver; the CUDA libraries come with
the app.

\chapter{Installation}
\begin{enumerate}
  \item Download the installer. This link always serves the newest version:
  \url{https://github.com/asanzhuerta/Cover_Maker/releases/latest/download/Cover_Maker_x64-setup.exe}.
  The project's GitHub Releases page has the same file for every version as
  \texttt{Cover\_Maker\_<version>\_x64-setup.exe}, and
  \texttt{SHA256SUMS.txt} lists the SHA-256 hash of both names, so you can
  check a download with \texttt{Get-FileHash} in PowerShell.
  \item Run it and choose the language, English or Spanish. The app uses it as
  its default language; you can change it later in \emph{Settings}. The
  installer works per user and does not ask for administrator rights. It installs into
  \texttt{\%LOCALAPPDATA\%\textbackslash Cover\_Maker}, the same folder that
  holds the runtime and your data, and adds a Start-menu entry.
  \item Windows SmartScreen may warn that the publisher is unknown, because
  the installer is not code-signed yet. Choose \emph{More info} and \emph{Run
  anyway} only if you downloaded it from the official Releases page.
\end{enumerate}

For an unattended install, run the installer with \texttt{/S}.

\section{Package managers}
Once the packages are published, \CM{} can also be installed with
\texttt{winget install asanzhuerta.CoverMaker} or, from Scoop's Extras
bucket, with \texttt{scoop install cover-maker}. The winget package runs the
same installer. The Scoop package unpacks the app into Scoop's folder instead;
update it with \texttt{scoop update cover-maker} rather than from the app,
which would install a second copy. Both keep the runtime and your data in
\texttt{\%LOCALAPPDATA\%\textbackslash Cover\_Maker}.

\chapter{First run}
Before anything is downloaded, the \emph{Setting up Cover\_Maker} screen shows
what the first run needs on this computer: the download size, the approximate
space on disk once installed, the free space on the drive, the PyTorch build
chosen for your hardware (CUDA for a compatible NVIDIA card, otherwise the
processor build) and the folder it goes to. Models are extra and are only
downloaded later, when you accept them. Press \emph{Download and install} to
start. If the drive does not have room for the runtime plus 512~MB to spare,
the screen says so and nothing is downloaded: free some space and press
\emph{Check again}. Updates and repairs of an existing install start without
asking.

The setup then lists the steps and shows their progress:
\begin{enumerate}
  \item \textbf{Python 3.12}: a private copy, not added to \texttt{PATH}.
  \item \textbf{Engine environment}: a virtual environment.
  \item \textbf{Engine and core libraries}, installed from lock files that pin
  every package by version and hash.
  \item \textbf{ffmpeg} (LGPL build, for decoding and MP3) and \textbf{deno}
  (used by yt-dlp for some video sites), checked against pinned SHA-256 hashes.
\end{enumerate}
This takes one to a few minutes, depending on the connection. When it is done
the usual welcome screen appears. Its last step, \emph{Models}, gets you to
your first stems quickly: it shows the model recommended for your hardware with
its licence notice; once you accept it, one button downloads it, and
\emph{Try it with the example song} separates a 28-second Creative Commons
clip that comes with the app (no download needed). The User Manual describes
this step.

The \textbf{separation runtime} (PyTorch and audio-separator) is installed
next, in the background; the sidebar shows \emph{Installing the separation
runtime} with the chosen build. If an NVIDIA GPU with compute capability 7.5
or higher (Turing, RTX~20 series or newer) is found, the CUDA build is used
(about 4~GB of downloads), otherwise the CPU build (under 1~GB). You can go
through the welcome screen meanwhile. Installing models and separating need
this step: until it finishes, the \emph{Models} and \emph{New job} pages show a
notice and the \emph{Install} buttons are disabled. While it runs, the \textsf{RUNTIME} light in the display at the bottom right
blinks amber; it turns green when the separation runtime is installed.

Everything is stored in
\texttt{\%LOCALAPPDATA\%\textbackslash Cover\_Maker\textbackslash runtime}.
Models are not part of the setup: you choose and download them on the
\emph{Models} page after reading their licences.

\section{What the installer downloads}
The installer carries uv, the engine and its lock files. On first run uv
downloads a Python runtime (checked against the hashes uv ships with) and the
engine's packages, each pinned by exact URL and SHA-256 hash in the lock files;
ffmpeg and deno are checked against the hashes listed in the installer's
\texttt{deps.json}. A file that does not match is rejected.
App updates are verified with the update signature before
they are installed. AI models are downloaded only when you accept them on the
\emph{Models} page, from their original sources.

\section{DAW plugin and script (optional)}
The release page also offers \texttt{Cover\_Maker-VST3-<version>-x64.zip} and
\texttt{Cover\_Maker-REAPER-<version>.lua}. Copy \texttt{Cover\_Maker.vst3}
from the zip to
\texttt{C:\textbackslash Program Files\textbackslash Common Files\textbackslash VST3}
(this folder needs administrator rights) and rescan plugins in your DAW; load
the script in REAPER from \emph{Actions → Load ReaScript}. Both need the app
to be running. The User Manual explains how to use them. The plugin is
licensed under the GNU GPL version 3 or later.

\chapter{Updates and removal}
\section{App updates}
\emph{Settings $\rightarrow$ Updates $\rightarrow$ Check for updates} asks
GitHub Releases for a newer version. Updates are signed; the app verifies the
signature before it installs one, then restarts. After an update the setup
screen appears briefly while the engine is re-synced with the new lock files;
the separation runtime is kept and updated in place.

\section{yt-dlp updates}
Video sites change often. \emph{Check for yt-dlp update} compares the installed
yt-dlp with the newest release on PyPI and offers \emph{Update}; the engine
restarts afterwards. The next app update sets yt-dlp back to the version tested
with that release.

\section{Removal}
Uninstall from \emph{Settings $\rightarrow$ Apps} or the Start menu. The
uninstaller always removes the app and its runtime folder. Your library,
models, database and logs in
\texttt{\%LOCALAPPDATA\%\textbackslash Cover\_Maker} are removed only if you
tick \emph{Delete the application data}. Exported stems in your own folders are
never touched.

\chapter{Troubleshooting}
\begin{description}
  \item[Setup could not finish.] The error is shown on the setup screen. Check
  the internet connection, proxy or firewall, then choose \emph{Retry}:
  completed downloads are kept in the cache, so the retry continues where it
  stopped. The setup needs access to \texttt{github.com},
  \texttt{pypi.org}, \texttt{files.pythonhosted.org} and
  \texttt{download.pytorch.org}.
  \item[Antivirus blocks the setup.] Some antivirus products quarantine
  \texttt{uv.exe} or files in the new environment. Allow the folder
  \texttt{\%LOCALAPPDATA\%\textbackslash Cover\_Maker} and retry.
  \item[Separation runtime not installed.] The sidebar shows the error and a
  \emph{Retry} button. The CUDA build is a large download; on slow or metered
  connections you can force the smaller CPU build by setting the user
  environment variable \texttt{COVER\_MAKER\_TORCH=cpu} and restarting the app.
  \item[The GPU is not used.] Update the NVIDIA driver and check that
  \texttt{nvidia-smi} works in a terminal. If the CPU build was installed
  first, close the app, delete
  \texttt{\%LOCALAPPDATA\%\textbackslash Cover\_Maker\textbackslash runtime} and
  start the app again.
  \item[Start over.] Close the app and delete the \texttt{runtime} folder; the
  next start runs the setup again. Your library and models are not affected.
  \item[Video links stop working.] Use \emph{Check for yt-dlp update}.
  \item[Reporting a problem.] \emph{Settings $\rightarrow$ Diagnostics
  $\rightarrow$ Create diagnostic report} writes a zip into
  \texttt{\%LOCALAPPDATA\%\textbackslash Cover\_Maker\textbackslash logs}
  with the versions, hardware, runtime state, installed models, recent jobs
  and the engine log (\texttt{engine.log}). Your folders, the paths of links
  and any token are removed, and no audio or model file is included. Attach
  it to an issue on the project's GitHub page.
\end{description}
